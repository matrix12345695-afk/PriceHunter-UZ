# PriceHunter UZ 1.4 — браузерные каталоги

Добавлены автоматические карточки Uzum, Wildberries UZ, OLX и браузерный резерв Asaxiy.
Название, полная текущая цена, ссылка и фото разбираются из отображаемого каталога.
OLX показывает состояние товара и место объявления. Рассрочка и зачёркнутая цена не используются.
Сохранены API Olcha, IDEA, Texnomart, Mediapark; webhook и существующая PostgreSQL.

## Что подтверждено

| Площадка | Подключение | Проверка |
|---|---|---|
| Olcha, IDEA, Texnomart, Mediapark | API | Пользователь подтвердил выдачу на Render |
| Asaxiy | HTML + Chromium при отказе | Обычный браузер открыл каталог; Render ещё не проверен |
| Uzum, Wildberries UZ, OLX | Chromium | Реальные карточки прочитаны; парсеры проверены на сохранённом HTML |
| Elmakon | Структурированные данные HTML | Не исправлен: при проверке 502 и ошибка сертификата |
| AliExpress | Поиск на сайте | Автоматического адаптера нет; браузерная проверка запрещена политикой среды |

Это реализация браузерных адаптеров, а не подтверждение их работы на вашем сервере.
IP Render может получать иной ответ. При CAPTCHA/403 бот показывает отказ и не решает защиту.
Фото отправляется URL или файлом JPEG; при отказе источника остаётся текстовая карточка.

## Важное для Render

Для этой версии нужны Chromium и его системные библиотеки. Dockerfile устанавливает их
при сборке (`python -m playwright install --with-deps chromium`). Если ваш сервис уже Docker,
обновите файлы и выполните Deploy. Для существующего Python runtime одной установки pip
недостаточно: потребуется установка браузера и системных зависимостей в build environment;
если она недоступна, понадобится Docker Web Service с прежними переменными и базой.
Само обновление render.yaml не меняет runtime существующего сервиса.

Браузер открывает одну страницу за раз, контексты закрываются после каждого запроса.
На площадку выделено до 38 секунд, на весь поиск — до 200 секунд; результаты кэшируются 3 минуты.
Браузер потребляет дополнительную память. Необходимый тариф нельзя подтвердить без замера на Render.
При `browser_unavailable` проверьте установку Chromium и лимит памяти.
Один обработчик очереди выполняет поиски последовательно: при одновременных запросах пользователи ждут.

## Как обновить

1. Распакуйте архив. Загрузите **содержимое** папки `PriceHunter-UZ` в корень текущего GitHub-репозитория с заменой одноимённых файлов. Не создавайте вложенную папку внутри репозитория.
2. Сохраните commit. Если Auto Deploy уже включён, Render начнёт сборку сам; иначе используйте Manual Deploy в существующем сервисе.
3. Оставьте существующие `BOT_TOKEN`, `DATABASE_URL`, `WEBHOOK_URL`, `WEBHOOK_SECRET` в Render Environment. Ничего секретного в GitHub добавлять не нужно.
4. Дождитесь успешного Deploy и проверьте `/health` по адресу своего сервиса, затем отправьте `/start` боту.

Новый Render-сервис, новый бот и новая база не требуются. START.bat не нужен.

## Совместимость запуска

Поддерживаются существующие варианты:
- `python run.py`
- `python -m app.main` (команда из старого Dockerfile)
- `uvicorn app.web.server:app --host 0.0.0.0 --port $PORT`

Dockerfile запускает веб-сервер и использует PORT, выданный Render. Нужен один процесс / один worker.
`render.yaml` теперь описывает Web Service и `/health`. В загруженном исходном архиве YAML ошибочно описывал `worker`, хотя run.py и app/web использовали веб-сервер и webhook.
Если фактический сервис в вашей панели уже работает как Web Service, оставьте его. Изменение YAML само по себе не перенастраивает вручную созданный сервис.

`WEBHOOK_URL`: базовый HTTPS-адрес Render; уже добавленный суффикс `/webhook` также поддерживается.
Если переменная отсутствует, используется `RENDER_EXTERNAL_URL`. Существующий WEBHOOK_SECRET используется без изменения.
Если секрет не задан, приложение получает постоянный секрет из BOT_TOKEN и регистрирует его в Telegram автоматически.
DATABASE_URL принимает `postgres://`, `postgresql://` и `postgresql+asyncpg://`.

## База данных

Новая версия подключается к **той же PostgreSQL** по DATABASE_URL. Локальная SQLite для сервера не используется.
При первом запуске создаются отдельные таблицы: ph_preferences, ph_history, ph_favorites, ph_updates.
Требуются права CREATE TABLE в существующей базе. Старые products, prices, stores, subscriptions не удаляются и не изменяются.
Старые миграции и исходные модули сохранены. Их автоматический запуск не требуется для новых таблиц.
Новые избранное и история не импортируют автоматически старые подписки. Старый мониторинг подписок не подключён к новому веб-запуску.

Webhook сохраняет входящий update в PostgreSQL и быстро отвечает Telegram. Фоновый обработчик выполняет поиск;
повторный update_id не добавляется второй раз. Необработанные задания остаются после перезапуска.
Успешно обработанные payload очищаются. После трёх неудач задание остаётся со статусом failed для диагностики.
При аварии между отправкой ответа Telegram и записью статуса возможен повтор ответа (семантика at-least-once).
Версия рассчитана на один экземпляр: не включайте несколько workers/реплик. При перекрытии старого и нового процесса во время деплоя также возможен повтор ответа.

## Функции бота

Поиск сообщением, выбор площадок, выдача по страницам, бюджет в UZS, сортировка, избранное и история.
Сохранение настроек в PostgreSQL. Цены с временем получения, переходы в магазин, кэш до 3 минут и изоляция ошибок.
`/forget` удаляет новые настройки, историю и избранное пользователя; старые таблицы предыдущей версии не затрагиваются.
Интерфейс русский, работа в личном чате. Автоматическое отслеживание снижения цен в этой версии не включено.


## Диагностика

В Render Shell: `python -m pricehunter.diagnose "Iphone 17 pro max"`.
Команда выводит состояние каждого источника и образцы полученных карточек, без Telegram-сообщений.
Стартовая проверка по умолчанию отключена, чтобы не занимать браузер во время первого поиска.
Для однократной проверки в Logs включите `PROVIDER_DIAGNOSTICS=1`, дождитесь строк `PROVIDER_CHECK`,
затем верните `0`. Не запускайте диагностику одновременно с пользовательским поиском.

Проверки разработки: `python -m pytest tests -q`. Живой деплой, ваша PostgreSQL и доставка
фото через вашего Telegram-бота здесь не проверены. См. TEST_REPORT.md.
